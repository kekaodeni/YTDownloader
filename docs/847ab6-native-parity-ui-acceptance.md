X 的首次分歧在应用格式投影层：原生 yt-dlp 提供的 HLS 独立音频格式 `acodec` 可为空，旧代码将其过滤，使 UI 的视频格式丢失可配对音轨。现在保留该原始候选；自动视频加音频下载将选流交给 yt-dlp 原生默认行为，FFmpeg 合并和最终 ffprobe 校验仍生效。用户配置与 `--ignore-config` 的格式选择不同，因此只有相同选流条件下比较成品哈希。

Bilibili 原始格式中，质量标记 `116` 的 `30116`、`100028`、`30106` 分别报告 62.50、60.15、58.82 FPS，编码不同；质量标记 `80` 的 `30077` 为普通 1080p，约 30.30 FPS。UI 仅将同一站点质量档 `116` 显示为一个“1080p 60 FPS”，保留三个原始候选 ID；普通 1080p 保持独立。未对其它站点套用通用 FPS 容差。

ffmpeg 对两个 GUI 成品的前 30 秒解码和音量分析均检出非静音音频：X 平均 -34.5 dB、峰值 -3.7 dB；Bilibili 平均 -25.6 dB、峰值 -0.9 dB。Windows Media Player 打开两个成品时均报告有音频和视频，播放位置推进约 4 秒。此项是技术播放检查，不代表人工主观试听。
